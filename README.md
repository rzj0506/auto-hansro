# ro.hans幸存者助手

基于用户提供的 **v1.3.0** 开发，当前版本 **v1.5.0**，适用于 <https://ro.hans-webgametw.com/>。

[安装／更新脚本](https://raw.githubusercontent.com/rzj0506/auto-hansro/userscript-release/ro-survivors-helper.user.js) · [更新元数据](https://raw.githubusercontent.com/rzj0506/auto-hansro/userscript-release/ro-survivors-helper.meta.js)

使用 Tampermonkey 安装后刷新游戏。首次使用保持暂停，按 F9 展开面板，按 F8 启动／暂停。安装改名后的脚本时，请停用原来的“RO 倖存者：三系法術與寶箱助手”，避免两个版本同时运行。

## 独立重抽开关

面板的“重抽設定”中有两个可独立保存的勾选项：

- **局內技能：允許重抽**：仅在没有符合技能配置的选项时重抽整组；取消勾选后，有合规牌照常选择，无合规牌等待手动选择。
- **寶箱：允許重抽**：控制宝箱单张和整组重抽；取消勾选后，按已有优先级和“重抽用盡／達上限後”设置选择现有卡片或等待手动选择。

两个开关默认开启，以延续 v1.3.0 行为。旧配置中的技能开关、宝箱策略（含“不重抽”）、重抽上限和保留次数继续生效。勾选宝箱重抽后，仍需策略允许且有剩余次数才会重抽；开关不保证一定重抽。每次修改立即保存，可导入／导出 JSON。使用同一游戏域名的原有浏览器配置和面板位置会保留。

## 宝箱并列优先级

每个栏位的“加入哪个优先级”下拉框可选择已有级别或“新增优先级”，再从物品表选入物品。连续加入同一级时自动并列，重复物品不会再添加；同名但 ID 不同的物品可以分别加入。

例如，先把冷却药水、生命药水加入第 1 级，再把伤害药水、范围药水加入第 2 级，保存结果为：

```text
冷卻藥水 [p_cd] | 生命藥水 [p_hp]
傷害藥水 [p_dmg] | 範圍藥水 [p_area]
```

同一行的所有物品都并列，行与行之间才有先后。任一第 1 级物品命中均视为首选，后续仍按成型、累计等级、均衡和稀有度比较。也可直接编辑文本，用 `|` 或 `｜` 分隔同级项目；旧的单项、多项和纯 ID 配置均兼容。

## 宝箱智能追首选、补齐与均衡

“智能追首选”默认开启，旧配置自动兼容，优先级内容、重抽上限、保留次数和用尽后的处理方式不变。

选牌顺序为 **配置优先级 → 同级补空／成型需求 → 保留已有物品累计等级 → 均衡等级 → 稀有度**。空栏第二优先级不会压过已占栏的第一优先级。同级先补空栏，再将可替换的非首选神格换成首选，最后升级已有首选；同等需求时避免换掉已有累计等级的物品。

智能重抽利用游戏实际规则：

- **单张重抽保持类型**：药水仍是药水。最需要的目标类型已在牌面上时，定向单抽该类型的非首选牌。
- **整组重抽重新随机类型**：目标类型没有出现时，优先整组寻找；出现后转为单抽。不保证每次整组都能换出所需类型。
- **保护已出现的首选**：不重抽首选牌、不整组重抽丢掉首选；只有其他牌能抽到更需要的首选时，才继续单抽。没有这种机会就直接选择首选，不为稀有度或小幅等级差继续消耗。
- **过滤不可达目标**：普通物品填进栏位后通常锁定种类，单张或整组均无法换成另一种普通物品；神格结合已学技能、替换次数与放逐状态判断。助手只读取原生可抽池，不试抽、不推进随机数，也不自动放逐或 Focus 宝箱牌。

“仅单张／仅整组／不重抽”和宝箱重抽总开关始终有效。允许两种方式时，智能模式根据目标类型决定先用哪种；关闭智能模式后，按原先单张／整组顺序执行并遇首选即选。同优先级补齐／均衡开关关闭时，不为补齐或均衡追加重抽。

未命中首选且无法继续重抽时，仍按现有“选最优项／等待手动”设置处理。“选最优项”允许次优填空栏，这可能锁定该栏本局物品种类；选择“等待手动”则停下。未配置优先级时不重抽。

助手读取游戏 `runItems.slots`，无法获取时再读取 HUD；不凭卡片的“新”标记猜测栏位是否已有物品。无法确认可抽池时，不在保住首选后追加重抽。每箱重抽分别计数，重绘卡牌不清零，连续开下一箱会清零。日志显示目标类型及决策原因。五栏全部填满不等于物品已达到最高等级。

## 时间／技能总等级触发不再翻牌

“之后不再翻牌触发条件”中提供两个独立开关，可任选或同时勾选：

- **按局内时间**：填写分钟数，支持 0.1 分钟；0 表示开局后启用。默认关闭，默认阈值 10 分钟，沿用旧版时间配置。
- **按技能总等级**：填写正整数阈值。总等级是本局技能栏内已拥有技能加上普攻的当前等级之和，每个技能只计一次，包含被动技能，不使用角色 Base Lv，也不重复计算派生武器。默认关闭，默认阈值 100。

两项同时开启时，**任一条件达到就启用**，无需同时达到。面板显示当前技能总等级（含普攻）；优先读取游戏等级接口，读取不到时尝试 HUD，无法确认的数据不会触发等级条件。

通过游戏原生开关启用后，每局只自动执行一次，下一局重新计算。只停止之后的技能升牌，宝箱照常，已打开的技能牌仍需正常选完。游戏手动暂停时不会把电脑经过的时间算进局内分钟。

## 三系技能升级顺序

火箭术、冰箭术、雷击术的“增加目标数”升级固定先于稀有度。例如普通 `+1 目标` 会排在传说伤害升级之前；同为这三系的目标数升级时，再比较稀有度。

“其余技能牌先比稀有度”开关继续控制其他卡牌的排序，不会覆盖三系目标数升级的优先规则。此规则针对已有技能的升级牌，不把新技能介绍中出现的“目标”当成这类优先升级。

## 周目远征

选择副本和一／二／三周目。游戏目前使用相同的 10 个副本 ID，二周目显示“・改”，三周目显示“・改²”；助手先切换原生周目页签，再选副本。未解锁或装备分数不达标时等待手动处理。点击“读取游戏副本清单”可更新当前页签显示的名称与开放状态。

已处理难度选择后的“高难度提醒 → 入场”，仅在助手已发起该副本出发时确认，不会确认无关对话。重复远征继续沿用游戏当前难度滑杆配置。

## 结算后穿装和出售

两个功能均默认关闭，可分别勾选，不依赖重复远征开关；执行顺序是返回广场、穿装、出售、下一场。

- 自动穿装使用原生“一键穿装”，选择能穿且装备分数更高的装备，武器保持同类型；原装备插卡不会自动转移。
- 自动出售需同时勾选总开关和品质。普通、优良、稀有、史诗、传说分别控制，默认都不选；“优良”是游戏额外提供的品质。
- 出售复用矿石商人的原生“一键贩卖”和确认流程，处理背包中所有符合所选品质的可售装备。任何角色穿戴中、受保护、初始、角色专属、插卡和精炼装备均保留，卡片不出售。
- 同时启用时，先换上的更优装备会被原生出售规则保护。确认前改变出售设置会取消该次出售；保存失败或结果未确认时停止下一次远征，并显示商人提示。

整理时通过原有方向键走到矿石商人，整理完再回远征队长。手动方向键或点击移动会优先让出操作；暂停助手会释放自动按键。

保留 v1.3.0 的三系技能及 4／5 技配置、宝箱五栏优先级、放逐、避怪、拾取、重复远征、拖动面板和后台运行逻辑。后台运行仍受浏览器冻结／丢弃标签页和电脑休眠影响。

## 开发与发布

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm test
pnpm build
```

源码位于 `src/ro-survivors-helper.user.js`。版本更新时，同时递增 `@version`、`const VERSION` 和 `package.json` 的版本。推送 main 后，GitHub Actions 完成测试并将安装文件、元数据和 SHA-256 清单发布到 `userscript-release` 分支。安装路径固定，后续更新由 Tampermonkey 检查；运行中的游戏需刷新加载新版本。

73 项测试覆盖并列优先级编辑与保存、三系目标数优先、技能总等级含普攻、时间／等级任一触发、旧配置兼容，并回归智能重抽、每箱计数、周目远征及结算穿装／出售。`test/fixtures/native-ui.json` 包含 2026-11-16 从游戏公开客户端提取的相关 UI 及只读可抽池函数，用于离线验证。测试使用模拟游戏接口，尚未进行真实账号实战验证。
